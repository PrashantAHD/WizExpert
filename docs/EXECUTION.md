# Local-account execution follow-up

This command implements a small, local follow-up workflow:

1. Read saved Run Command output and retain it in private local memory.
2. Mark proven account-removal completion in the existing report.
3. Keep blocked resources in their original pending tab with a reason and next action.
4. Write a stakeholder email draft for human review.

It does not execute guest commands, send email, create tickets, change Wiz
statuses, or track scans/closure. No network access, AI service or MCP connection
is required. All examples are synthetic.

## Existing workbook contract

Required tabs: `AWS Data`, `Azure Data`, `Pending Review`, `Pending Remediation`.
An optional `Cover` is preserved; recognized execution-summary lines are refreshed.
The four-tab privileged-credential report generated by the default CLI is a
different schema and is deliberately rejected.

Each data tab needs unique, nonempty headers:

- `Account`
- `Resource Name`
- `Region`
- `Remediation Status`
- `Local User Action`

Consolidated AWS/Azure headers must match. Pending tabs must represent the
consolidated pending rows without duplicate resource keys. Optional historical
columns may be omitted or reordered. Updates use header names, not column letters.
Tables, merged data cells, validation rules, conditional formatting, formulas and
external workbook links are rejected rather than silently damaged.

`Local User Action` must begin with an exact approved scope such as:

```text
Remove only: alice; bob
Excluded from execution: emergency-user (not remediated).
Retain password authentication.
```

The action is an operator-maintained approval record, not proof of authorization.
The historical `Local Users` column is never used to authorize removal. Review
authority and change conditions through your organization's existing process.

Completed actions use `Removed: alice; bob (Run Command verified).`. A prior
single-account confirmation of the form `alice removed (user-confirmed).` is
included in the email's recorded totals, but is not treated as a new execution
approval. Existing exclusion/action suffixes and historical evidence are preserved.

No results are imported into cells, comments or hidden sheets. Existing comments
are retained. New `Blocker` and `Next Action` columns are added if missing; only
the status column gets disposition colors. Pending views are rebuilt from the
consolidated rows. New/wrapped content receives estimated content-fit row heights;
review unusually long notes in Excel.

## Import results

```powershell
.\.venv\Scripts\python.exe -m wizexpert update-remediation `
  --report "C:\Reports\local-account-report.xlsx" `
  --result "C:\Evidence\result-one.txt" `
  --result "C:\Evidence\result-two.txt" `
  --email-output "C:\Reports\update-one.txt" `
  --ticket "CHANGE-EXAMPLE"
```

The ticket is optional. Missing references, execution dates and approvals are not
invented. Input text must be UTF-8, optionally with a BOM. Normal and
newline-collapsed portal output are supported. Keep one execution per file.

To draft an update from the existing report and available private memory without
changing either:

```powershell
.\.venv\Scripts\python.exe -m wizexpert update-remediation `
  --report "C:\Reports\local-account-report.xlsx" --email-only `
  --email-output "C:\Reports\stakeholder-draft.txt"
```

Supported protocol:

- `VM=... EXECUTION=SINGLE_RUN`
- `ACCOUNT=... UID=... GID=... HOME=... SHELL=...`, or the explicit already-absent marker
- `PRECHECKS=PASSED; proceeding automatically with approved removals.`
- `BACKUP_PATH=/var/lib/cloud-security-remediation/account-removal-...`
- `REMOVING=...`, then `REMOVED_AND_VERIFIED=...`
- `REMOVED_THIS_RUN=...`
- `RESULT=ACCOUNT_REMOVAL_VERIFIED_HOME_PATHS_PRESERVED_SSH_CONFIG_UNCHANGED`

Stopped runs instead need `STOP=...`, `REMOVAL_COMMANDS_SUCCEEDED=...` and
`RESULT=STOPPED_REVIEW_REQUIRED` (the standard explanatory suffix is allowed).
No-change runs use `RESULT=NO_CHANGES_ALL_TARGETS_ALREADY_ABSENT`.

The importer is deliberately not a general log interpreter. Missing VM identity,
unsupported output, nonempty stderr, contradictory results or unknown accounts
fail before workbook changes. Use a reviewed manual blocker when output cannot
establish a safe match. A bare "Enable succeeded" is not completion evidence.

### Matching and limits

Results match an exact, unique Azure resource name. If names repeat, qualify
with `--account` and/or `--region` using the exact workbook strings. These filters
apply to all result files in that invocation. The available output does not
prove a native resource ID: the operator must confirm the VM context. Matching
and checksums do not authenticate a log or prove guest state independently.

Only explicit, internally consistent per-account verification counts as removal.
`REMOVAL_COMMANDS_SUCCEEDED` alone does not. Partial runs become **Blocked** and
retain the verified subset privately for the email and later reconciliation.
Do not automatically rerun deletion to resolve a stop or a directory-backed
namesake. No-change/already-absent output never counts as a new removal or upgrades
an unproven resource to Remediated.

Repeated execution evidence is deduplicated across runs using its parsed
contents, not its filename or whitespace. A new deletion/stop result on a
previously completed VM requires manual reconciliation, not automatic reopening.
Scope changes after recorded execution also require reconciliation.

## Manual blockers and next actions

Save a UTF-8 CSV with exactly these headers, in this order:

```csv
Account,Resource Name,Region,Status,Blocker,Next Action
example-account,example-vm,example-region,Blocked,VM is deallocated,Leave stopped until the owner approves startup under the change process
```

```powershell
.\.venv\Scripts\python.exe -m wizexpert update-remediation `
  --report "C:\Reports\local-account-report.xlsx" `
  --blockers "C:\Evidence\blockers.csv" `
  --email-output "C:\Reports\blocker-update.txt"
```

For `Blocked`, both reason and next action are mandatory. A blocked resource stays
in whichever pending tab it belonged to. To clear a blocker, explicitly supply
its original `Pending review` or `Pending remediation` status, an empty `Blocker`,
and a nonempty next action. Clearing a blocker does not mark work complete or
grant approval. Completed/accepted resources cannot be reopened through this CSV.
Do not supply both a result and a manual blocker for the same resource in one run.

## Private memory, report and email

The adjacent `<report-stem>.remediation-memory.json` file records raw execution
output, receipt time, parsed results, approved scope, verified accounts and blocker
history. Receipt time is not the guest execution timestamp. The file is local
application memory, not an AI model memory service, and is not encrypted.

Keep the report and memory together in approved private storage with appropriate
access controls and retention. Do not commit, upload or attach memory files or
account-database backups to stakeholder messages. Back up the pair together;
deleting or separating memory loses deduplication and partial-run history.
Renaming the workbook requires renaming its adjacent memory file too.

The email includes report-wide recorded completion (including prior confirmations),
partial changes, scope exceptions, blockers and requested next actions. It excludes
raw logs and backup contents. It is always a draft: confirm its statements, actual
recipients, ticket reference, attachments and approved scope before sending.

Output stays outside the public repository. Existing drafts are never overwritten.
Each update keeps a private pre-update XLSX backup. Validation happens before
publication, and source-content checks reject concurrent changes. If report
publication fails, the command restores the previous memory and removes its
unsent draft; the workbook backup remains. Multiple files cannot be committed
atomically across an OS crash: retain backups, do not use simultaneous writers,
and reconcile the report/memory pair after an interrupted update. Errors are
reported explicitly; there is no automatic retry or cloud rollback.
